# @dnikulshin/harness-viewer

Read-only просмотрщик артефактов [`@dnikulshin/harness`](https://github.com/DNikulshin/dev-harness):
дерево `.pi/artifacts/**` одной самодостаточной HTML-страницей — список циклов, состояние, причина
остановки, гейты, пакет `evidence` с диффом, решения, манифесты и отчёты агентов.

Просмотрщик **показывает, а не решает** (ADR 0006 в ядре): источниками истины остаются файлы,
которые пишет ядро, а страница — их представление.

## Что делает и чего не делает

| Делает                                                              | Не делает                                                       |
| ------------------------------------------------------------------- | --------------------------------------------------------------- |
| читает `state.json`, `gates.<n>.json`, `decision.<n>.json`, `metrics.json`, `manifest.<n>.json`, `escalation.json`, `evidence/` | не пишет в каталог артефактов — единственный выход задаётся `--out` |
| собирает одну страницу на все циклы дерева                           | не поднимает сервер и не держит состояние представления          |
| показывает ошибку чтения рядом с блоком                              | не падает на битом файле и не додумывает отсутствующие поля      |
| разбирает файлы по Приложению A `docs/orchestrator-core.md`          | не пересчитывает вердикты и не двигает стадии                   |

Границы с соседями:

- **ядро** (`@dnikulshin/harness`) — пишет артефакты и запускает гейты; просмотрщик только читает
  (ADR 0004, ADR 0006 в ядре);
- **адаптер рантайма** (`@dnikulshin/pi-harness`) — команды `/cycle` внутри агента; просмотрщику
  рантайм не нужен и в `dependencies` его нет: страница открывается с диска;
- **`cycle-report --html`** в ядре — отчёт по прогонам с числами и сравнениями; здесь — просмотр
  артефактов по циклам, включая дифф и `evidence/`, без установленного ядра.

## Требования

- **Node.js 26.13.x** (`engines.node` = `>=26.13 <27`, `.nvmrc` = `26.13.1`);
- **Linux или macOS** (`os: ["linux", "darwin"]`).

Зависимостей нет ни в `dependencies`, ни в `devDependencies`: тесты — `node --test`, страница —
шаблонные строки, стили внутри HTML.

## Установка и запуск

> Пакет ещё не опубликован в npm: публикация и защита тега — issue #3. До релиза запуск из
> репозитория: `node src/cli.mjs render --out viewer.html` (те же флаги).

```bash
npx @dnikulshin/harness-viewer render --out viewer.html
npx @dnikulshin/harness-viewer render --root ~/projects/acme --out /tmp/acme-cycles.html
npx @dnikulshin/harness-viewer render --artifacts .pi/artifacts --out viewer.html \
  --max-diff-bytes 200000
```

| Флаг               | По умолчанию        | Смысл                                                     |
| ------------------ | ------------------- | --------------------------------------------------------- |
| `--out`            | — (обязателен)      | куда записать страницу                                    |
| `--root`           | текущий каталог     | корень проекта                                            |
| `--artifacts`      | `<root>/.pi/artifacts` | каталог артефактов                                     |
| `--max-diff-bytes` | `200000`            | сколько байт `evidence/diff.patch` показать целиком       |

Коды выхода: `0` — страница записана (даже если часть файлов не прочиталась: ошибки видны на
странице); `1` — каталога артефактов нет или он недоступен, страница не пишется; `2` — ошибка
использования.

## Гарантии, которые проверяются тестами

1. **Дерево артефактов не меняется.** Прогон на двух циклах оставляет каталог побайтно тем же:
   сравнивается `sha256` каждого файла до и после, а не `mtime`.
2. **Битый или неполный артефакт не роняет прогон.** Ошибка чтения печатается рядом с блоком,
   остальные циклы остаются на странице, код выхода `0`.
3. **Страница самодостаточна.** Ни `<script>`, ни внешних `src`/`href`, ни сети: стили внутри,
   фильтров на JS нет; текст артефактов экранируется.
4. **Вывод побайтно детерминирован.** Два прогона на одном дереве дают одинаковый файл: нет ни
   времени сборки, ни случайного порядка.
5. **Нет рантайма агента и импорта ядра.** `dependencies`/`peerDependencies` пусты, в исходниках нет
   импортов `@dnikulshin/harness/scripts/**`, `scripts/lib/**` и Pi.

## Как читать страницу

- **Список циклов** — таблица: цикл, issue, стадия, итерация, последнее решение, стоимость, число
  проблем чтения.
- **Состояние** — ветка, стадия и её статус, итерация из лимита, подтверждение владельца, стоимость и
  длительность из `metrics.json`.
- **Причина остановки** — `action` и `reasons[]` последнего решения, счётчики, эскалация из
  `escalation.json` и `state.json`.
- **Гейты** — по итерациям, с `pass`/`fail`/`skipped`/`not_run` как есть: это разные факты.
- **Пакет `evidence`** — состав с размерами и `diff.patch` в раскрывающемся блоке.
- **Манифесты и отчёты агентов** — размеры пакета по итерациям и наличие `review.<n>.md` /
  `evaluation.<n>.md` (markdown не рендерится: разбор — работа ядра).

## Правила репозитория

Те же, что в ядре (`dev-harness`), и они воспроизводимы командой, а не кликами в UI:

```bash
node tooling/repo-rules.mjs --dry-run   # показать, что будет применено
node tooling/repo-rules.mjs --protect   # применить: режим merge, защита main, правила тегов
```

| Правило                | Что означает                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| squash-only merge      | в `main` попадает один коммит, история линейная; merge commit и rebase отключены                  |
| PR обязателен всем     | `enforce_admins` — правило действует и на владельца; ветка удаляется после merge                  |
| обязательные проверки  | `test (ubuntu-latest)` и `test (macos-latest)`, PR должен быть актуален относительно `main`       |
| линейная история       | merge-коммит, появившийся в обход настроек, не пройдёт                                            |
| без force-push         | переписать `main` нельзя; удаление ветки `main` запрещено                                          |
| теги `v*` защищены     | ruleset `release-tags`: тег нельзя удалить или перезаписать — по нему ставится пакет              |
| сканирование секретов  | включено вместе с блокировкой push, если ещё не было                                              |

Проверка правил — `test/repo-rules.test.mjs` (`node --test`): payload правил и идемпотентность
применения проверяются на подменённом `gh`, сеть не используется.

## Разработка

```bash
node --test        # тесты на фикстуре из двух циклов + правила репозитория
```

Фикстура — `test/fixtures/artifacts/`: два цикла (`example-alpha` с эскалацией по бюджету,
`example-beta` с `REWORK`) и каталог-мусор без `state.json`, который циклом не считается.

Решение о том, почему просмотрщик живёт отдельным пакетом и читает файлы, а не импортирует ядро —
ADR [0013](https://github.com/DNikulshin/dev-harness/blob/main/docs/adr/0013-viewer-repository.md)
в репозитории ядра. Контракт данных — Приложение A
[`docs/orchestrator-core.md`](https://github.com/DNikulshin/dev-harness/blob/main/docs/orchestrator-core.md).
