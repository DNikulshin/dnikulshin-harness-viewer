# AGENTS.md — dnikulshin-harness-viewer

## Что это

Read-only просмотрщик артефактов [`@dnikulshin/harness`](https://github.com/DNikulshin/dev-harness):
дерево `.pi/artifacts/**` превращается в одну самодостаточную HTML-страницу — список циклов,
состояние, причина остановки, гейты, пакет `evidence` с диффом, решения, манифесты и отчёты
агентов.

Пакет `@dnikulshin/harness-viewer`, `bin` — `harness-viewer`. Зависимостей нет вообще (ни
`dependencies`, ни `devDependencies`): тесты — `node --test`, страница — шаблонные строки.

Норматив живёт в ядре, здесь его копии нет:

| Что | Где |
| --- | --- |
| почему отдельный пакет и что он читает | ADR [0013](https://github.com/DNikulshin/dev-harness/blob/main/docs/adr/0013-viewer-repository.md) |
| почему UI показывает, а не решает | ADR [0006](https://github.com/DNikulshin/dev-harness/blob/main/docs/adr/0006-ui-presentation.md) |
| схема артефактов (Приложение A) | [`docs/orchestrator-core.md`](https://github.com/DNikulshin/dev-harness/blob/main/docs/orchestrator-core.md) |
| правила версий и публикации ядра | [`docs/release.md`](https://github.com/DNikulshin/dev-harness/blob/main/docs/release.md) |

## Структура

| Путь                     | Что там                                                              |
| ------------------------ | -------------------------------------------------------------------- |
| `src/artifacts.mjs`      | чтение дерева артефактов: `state.json`, `gates.<n>.json`, `decision.<n>.json`, `escalation.json`, `metrics.json`, `manifest.<n>.json`, `evidence/` |
| `src/render.mjs`         | HTML: список циклов, состояние, причина остановки, гейты, evidence, отчёты |
| `src/format.mjs`         | экранирование текста и форматирование размеров — единственное место, где текст артефактов попадает в HTML |
| `src/cli.mjs`            | аргументы, атомарная запись страницы, коды выхода                    |
| `src/direct-run.mjs`     | «запущен как CLI, а не импортирован»                                 |
| `tooling/repo-rules.mjs` | правила репозитория: squash-only, защита `main`, ruleset тегов       |
| `test/`                  | `node --test`: страница, read-only, битые артефакты, контракт, правила |

## Команды

| Команда                                    | Что делает                                                     |
| ------------------------------------------ | -------------------------------------------------------------- |
| `node --test`                              | все тесты (страница, read-only, контракт пакета, правила)       |
| `node src/cli.mjs render --artifacts test/fixtures/artifacts --out /tmp/v.html` | собрать страницу на фикстуре (в этом репозитории своего `.pi/artifacts` нет) |
| `node src/cli.mjs render --root <проект> --out /tmp/v.html` | то же по конкретному проекту        |
| `node tooling/repo-rules.mjs --dry-run`    | показать, какие правила будут применены к репозиторию           |
| `node tooling/repo-rules.mjs --protect`    | применить правила (нужны admin-права `gh`)                      |

## Правила

1. **Только чтение.** Просмотрщик не пишет в каталог артефактов, не запускает гейты, не двигает
   стадии, не пересчитывает вердикты, не хранит состояние представления. Единственный побочный
   эффект — страница по явному `--out`. Обещание проверяется тестом: побайтное сравнение дерева
   `sha256` до и после прогона.
2. **Зависимостей нет.** `dependencies`, `peerDependencies` и `devDependencies` пусты, Pi и любой
   другой рантайм агента — не библиотека для этого пакета. Тест по `package.json` и по импортам
   `src/**` держит запрет.
3. **Ядро не импортируется.** Только файлы артефактов по Приложению A. Не хватает поля — это дефект
   контракта ядра (issue в `dev-harness`), а не повод импортировать `scripts/lib/**`.
4. **Битый артефакт не роняет прогон.** Ошибка чтения видна рядом с блоком, остальные циклы
   остаются, код выхода `0`. Отсутствующее поле — «нет данных», а не ноль и не догадка.
5. **Страница самодостаточна и детерминирована.** Ни `<script>`, ни внешних `src`/`href`, ни сети;
   два прогона на одном дереве дают одинаковые байты. Текст артефактов экранируется.
6. **Ветка и PR — как в ядре.** Ветки `feat/*`, `fix/*`, `chore/*` от `main`; прямой push в `main`
   запрещён защитой (`enforce_admins`), merge — только squash и только владельцем; обязательные
   проверки — `test (ubuntu-latest)` и `test (macos-latest)`. Правила воспроизводятся
   `node tooling/repo-rules.mjs --protect`.
7. **Тег `vX.Y.Z` — контракт установки.** Ruleset `release-tags` запрещает удаление и перезапись:
   ошибочный тег лечится новым тегом, а не `push --force`. Публикация пакета — отдельная задача.

## Границы действий агента

- Минимальные правки в рамках задачи; без попутного рефакторинга и переименований.
- Новая зависимость — только с обоснованием в ответе и, по умолчанию, не нужна.
- Не трогать: `test/fixtures/` без причины (это контракт тестов), `.git/`, настройки репозитория
  вручную (для этого есть `tooling/repo-rules.mjs`).
- Публикация в npm и правка защиты ветки — действия владельца: агент готовит PR и команду.
